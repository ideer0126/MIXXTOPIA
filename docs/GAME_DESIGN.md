## 1. 设计支柱

1. **梦幻像素** —— 每关独立调色板 + 主题粒子，营造「生日愿望梦境」的整体气质。
2. **剧情驱动** —— 对话推进剧情：打字机效果、角色姓名框、部分节点有选项。
3. **谜题节奏** —— 教学 → 练习 → 综合：关 1 教基础，关 2–5 各练一种机制，关 6 综合收束。
4. **移动优先** —— 触屏虚拟按键单手可玩，键盘/触屏双输入等价。
5. **轻量友好** —— 休闲难度、倒下无惩罚（复位满血、保留星星），目标体验是「暖心收星」而非挫败。

## 2. 世界观与剧情线

### 2.1 世界观

- 灵感来源：NMIXX 第六张迷你专辑《Strange Muse》（2026-10-19 发行，主打《긴 소원 (Birthday Wish)》）。
- **官方概念层（据官方专辑概念文与公开报道提炼）**：MIXXTOPIA 是「容纳无数个体的共生世界，更是能让每个人尽情舒展专属自我身份的自由空间」；相聚于此的人各自奔赴向往的生活，又在灵魂深处相连、随时能再度并肩。**「我们互为彼此的专属缪斯」**——NSWER 的存在为缪斯们注入灵感，缪斯们的存在也点亮 NSWER 的日常。这里每天都在上演为全新缪斯准备的生日派对：吹熄蜡烛、许下心愿，永远在为彼此许下「Birthday Wish」。
- **神话倒影层（同人二创）**：希腊神话中，缪斯（Muses）是宙斯与记忆女神谟涅摩叙涅的女儿、司掌音乐与灵感的女神；九位缪斯的「九」暗合月相周期。本作中，六位成员即六位缪斯的化身；**MIXXTOPIA** 是灵感之泉（赫利孔山的灵感泉 Hippocrene）在梦境中的倒影。梦境里每一位缪斯都有一重「神话倒影」：Lily 倒映珀耳塞福涅（春之少女/冥后）、Haewon 倒映哈迪斯（冥王）、Sullyoon 倒映阿芙洛狄忒（爱与美，执丘比特之箭）、Bae 倒映德墨忒尔（丰收与大地）、Kyujin 倒映宙斯（天空与王座）、Jiwoo 倒映赫尔墨斯（信使与里拉琴）。完整对照与故事梗概见 §2.4。
- 参考《Strange Muse》概念预告与 MV 的公开解析（六人化身缪斯、紫罗兰天空下的马群/飞马意象、黑羊概念），本作加入：紫罗兰色天空与飞马（Pegasus）、黑羊彩蛋 NPC。

> 备注：用户提供的抖音图文解析（https://v.douyin.com/oq8yY83bGyA/ ）此前在本环境无法直接访问；2026-10-23 用户将 12 张截图直接提供，经本地 OCR 识别出完整内容（神话对应、四季循环故事），本节与 §2.4、§8 台词已按该解析落笔。OCR 原文存档于会话工作区 `.ds/ocr/`（不入库）。

> **关 1 的梦境形态**：MIXXTOPIA 把 NSWER 的生日愿望具象成童年记忆里的幼儿园礼堂——彩带、气球、塑料小椅子与奶油蛋糕。梦核的「熟悉又失真」不是恐怖，而是长大后再看小时候的那种温柔错位。

### 2.2 剧情线

NSWER 在生日夜对流星许下长愿，被星光引入梦境世界 MIXXTOPIA——一个每天都在举办生日派对的共生世界，NSWER 与缪斯们「互为彼此的专属缪斯」。六位缪斯许下的六个愿望化作 **25 颗愿望之星**，散落在六个梦幻区域；每散落一颗星，梦境的光就暗一分，灵感之泉随之干涸。玩家走遍六个区域、与缪斯对话、解开谜题、集齐全部星星，点亮许愿蛋糕——灵感之泉重新涌流，飞马掠过紫罗兰天空，生日愿望得以实现。六位缪斯各自的神话倒影（§2.4）随旅程逐关揭开：珀耳塞福涅的四季、赫尔墨斯的信使之路、宙斯的默许、月夜的重逢、大地的荒芜与复苏、疾风中的团聚。

### 2.3 结局

1. 25 星全部归位 → 许愿蛋糕逐层点亮 → 灵感之泉复涌，化作星光河。
2. 飞马掠过紫罗兰天空，载 NSWER 飞向黎明；耳边响起「긴 소원을 부릅니다, 응답하라 NSWER」。
3. **黑羊彩蛋**：6 关各藏一只黑羊 NPC，各说一句神话谜语；集齐 6 句，结局追加一段隐藏画面（M3 可选内容，不阻塞主线）。

**关 1 字段约定（以 `js/data.js` 为准）**：

- 实体的 `x,y`、`roomdoor.to.x,y` 与 `trigger.rect` 均使用本关地图的瓦片坐标；`portal.to` 则是下一关的关卡 ID。
- `room`：NPC 实体与对话节点使用相同的房间字符串（`hall` / `backstage`）；省略时按 `hall` 解析。同一角色的 `id` 可在两房间复用，互动候选与后续提示按房间区分。
- `label`：门的显示名称字符串；关 1 的 `door` 和 `roomdoor` 都有此字段，目前出入口渲染读取 `roomdoor.label`，不参与解锁判断。
- `facing`：传送门素材朝向，目前仅 `'east'` 有专用分支：配置 `sceneryAssets.portal` 且提供 `portalEast` 时选择右向素材；省略、其他值或缺少 `portalEast` 时选用默认 `portal` 素材。关 1 使用 `'east'` 面向右侧入口；该字段不改变碰撞、激活或目的地。
- `visual`：门的绘制提示；后台入口的 `gate` 使用 `'curtain'`，跳过普通 GATE 图形，由同格 `roomdoor` 根据门状态绘制帘幕 / 出入口，不改变碰撞或解锁条件。
- `requiresStars`：同关星星 ID 的字符串数组，全部已收集才满足；唱片、唱片机、后台门及寻找唱片的触发器均要求 `['s1','s2']`，不是星星数量。对 `gate`，只有配置 `requiresDialogue` 时才会同步这些前置条件；单独配置 `requiresStars` 不会驱动门状态。
- `requiresDialogue`：对话节点 ID 的字符串数组，全部已记录在 `played` 且对应对话已结束才满足；与 `requiresStars` 同时存在时两组条件都须满足。唱片、唱片机与提示要求六位 Muse 的自我介绍；后台门要求 `l1.music.play`；s3 和星光门要求 `l1.backstage.lily`、`l1.backstage.sullyoon`、`l1.backstage.byeori`。前置数组省略或为空表示该项无限制。
- `skipIfDialogue`：触发器的跳过节点 ID 数组，任一节点已记录在 `played` 就不触发；`music-ready` 使用 `['l1.record.take','l1.music.play']`，避免已取唱片或已播放后再提示寻找唱片。

关 4 的每个 `~` 格必须在 `entities` 中有且仅有一个同坐标 WATER（含 `x,y`），所有 WATER 的 `waterLevel` 初始均为 `high`、运行时始终一致；`shallow` 是固定地形属性。高水位 STEPSTONE 的站立效果覆盖同格水面；低水位时 `shallow:false` 的水面仍不可站立。切换水位后若玩家脚下不再可站立，按 §5.4 落水回本岸、保留已收集星星处理。

**#9 机制实现口径（2026-10-24，与 `js/engine.js` Mechanics / `tools/validate.js` 规则 9 对齐）**：

- **碰撞**：legend 解析为 `wall` / `water` 的瓦片阻挡；关闭的 `gate` 与 `box` 作为实体阻挡；玩家 AABB 分轴移动（撞墙可沿另一轴滑动）。
- **推箱**：玩家朝箱子移动且箱后一格可站立时，箱子沿该方向滑动一格；墙与其他箱子阻挡，**门格一律不接受箱子**（门开/关都不行，防止箱子压住门格、门闭合后堵死通路）。门开启时玩家仍可正常通过或站在门格上，只是箱子落点被拒。推箱当帧玩家不前进，避免与箱子重叠。
- **压力开关**：玩家或任意箱子压住开关期间，`target` 门开启；离开后若无人/无箱压住则关门。门初始 `open:true` 视为常开；玩家正踩在门格上时暂不关门，防止被夹住。
- **星星**：接触即收集，星星中心爆散金色粒子并播放拾取音效；`star:<星id>` 台词由对话系统（#12）分发。
- **传送门**：本关 `starCount > 0`、`stars >= starCount` 且传送门的前置条件全部满足时激活；`requiresDialogue` 指定的节点须已记录在 `played` 且对应对话已结束，如另有 `requiresStars` 也须同时满足。激活后播放粒子/音效并发出 `portal` 事件；玩家踩上传送门触发 `clear:<关卡id>` 台词/结算，`portal.to` 指向的关卡优先于数组线性下一关。
- **音效降级**：`js/audio.js` 在无 WebAudio 或声音关闭时安静返回 false，不影响机制与状态机。

> 战斗相关（敌人 ENEMY、攻击判定、能量炮）见 §12（Issue #18 已实现）。

## 7. 对话系统规范

- **样式**：底部对话框 + 姓名标签（§3 角色色；`nar` 使用 §3 旁白样式）；打字机 25ms/字；E/空格/点击翻页；选项用 ↑↓ 移动 + 确认键。
- **触发**：靠近 NPC 按互动；TRIGGER 区域自动触发；`once` 节点只播一次，`repeat` 节点可反复（提示类）。
- **节点类型 × 触发来源**（#12 转录时每个节点必须挂一种类型）：

| 节点类型 | 触发来源 | once | 说明 / 示例 |
|---|---|---|---|
| intro | NPC 互动（首次） | true | 开场剧情；结束后该 NPC 互动经 `next` 指向 hint |
| hint | NPC 互动（此后） | false（可重复） | 提示类，如 `l1.lily.hint`、`l2.jiwoo.hint`、`l3.hint`、`l4.lily.hint`、`l4.haewon.hint`、`l5.sullyoon.hint`、`l5.bae.hint`、`l6.hint` |
| npc | NPC 互动 | true | 一次性自我介绍 / 氛围台词，如 `l1.npc.lily`、`l4.npc.sullyoon`、`l5.npc.lily` |
| check | NPC 互动 | false | 可重复的选项检查，如 `l3.dj.check` |
| star | 收集星星事件（自动） | true | 收集反馈台词，如 `l1.star1` |
| clear | 过关事件（自动） | true | 结算台词，如 `l1.clear.1` |
| sheep | 黑羊互动 | true | 计数 sheep +1，如 `l1.sheep` |
| cutscene | 关卡加载 / TRIGGER / CAKE 自动，或道具互动 | true | 序章 `p0.*`、结局 `l6.end.*` |

- **`trigger` 取值约定**（与上表触发来源一一对应，规则 7 校验）：NPC 互动 → `npc:<speaker>`（首次/此后由节点类型决定）；收集星星 → `star:<星id>`；过关 → `clear:<scopeId>`；黑羊 → `sheep:<黑羊实体id>`；关卡 / 场景加载 → `load:<scopeId>`；TRIGGER 区域 → `trigger:<trigger实体id>`；唱片 / 唱片机 → `interact:<实体id>`；蛋糕 → `cake`。
- **字段约束**：每个节点必填 `type`（上表 8 种之一）、`trigger`（按取值约定）与布尔值 `once`（上表 `once` 列的 `true` / `false`，不从节点 id、类型或运行时行为推导），`type` 与 `trigger` 冗余声明、不可矛盾（如 `type:'check'` 配 `trigger:'npc:dj'`）。
- **自动对话作用域**：trigger 为 `clear:<scopeId>` / `load:<scopeId>` 的节点另须填写所属关卡或场景的 `scopeId`，其字符串形式必须等于 trigger 的后缀：关卡节点 `lN.*` 的 `scopeId` 必须为 N（如 `scopeId:1` 对应 `clear:1`），序章节点 `p0` 的 `scopeId` 必须为 `'p0'`（对应 `load:p0`）。关卡 ID 来自 `GAME.levels[].id`，独立场景 ID 来自 `GAME.scenes` 的键（见 §11），二者字符串形式不得重名；`clear` 仅用于关卡。每个已配置的「作用域 + 事件类型」恰有一个 `entry:true` 入口，事件仅调度该入口；同一演出的后续节点保留相同 `scopeId` 与 `trigger`、设 `entry:false`（缺省 false），由 `next` 串联且均须从入口可达，不能再次注册为自动入口。**`entry` 机制仅适用于 `clear:` / `load:` 自动作用域；`star:<星id>` / `sheep:<id>` / `cake` 的自动节点按 trigger 直接调度，不设 `entry`**（与 tools/validate.js #30 校验约定一致）。
- **黑羊绑定**：关 N 的黑羊实体使用全局唯一 `id:'sheepN'`、`dialogue:'lN.sheep'`（N = 1–6），对应节点为 `type:'sheep'`、`trigger:'sheep:sheepN'`、`once:true`。互动只播放该实体绑定的节点，首次播放计数 +1；保留每关一句、集齐 6 句追加结局画面的行为。

- `next` 指向的节点必须存在（§11 规则 7 校验）。
- **对话期间**：玩家定身；关 5 清凉条计时暂停；敌人移动/接触伤害与被动能量回复暂停（#18）。
- **快进**：按住互动键加速打字；整段跳过 = 双击翻页键（预留）。
- **数据格式**（#12 直接照此接入 data.js）：

```js
dialogue: {
  'l1.intro': {
    type: 'intro',               // 节点类型（§7 上表 8 种之一，必填）
    trigger: 'npc:lily',         // 触发来源：与 Lily 首次互动（§7 取值约定，必填）
    once: true,
    lines: [ { s: 'lily', t: 'NSWER！欢迎来参加你的生日会！' }, ... ],  // 节选；完整台词见 §8.2
    next: 'l1.lily.hint'          // 结束后将 NPC 互动指向 hint 节点
  },
  'l1.clear': {
    type: 'clear', scopeId: 1, trigger: 'clear:1', entry: true,
    once: true,
    lines: [ { s: 'lily', t: '三颗愿望之星，全部归位。' }, ... ]
  },
  'p0': {
    type: 'cutscene', scopeId: 'p0', trigger: 'load:p0', entry: true,
    once: true,
    lines: [ { s: 'nar', t: '生日夜的钟声，敲过第十二下。' }, ... ]
  },
  'l1.sheep': {
    type: 'sheep', trigger: 'sheep:sheep1', once: true,
    lines: [ { s: 'sheep', t: '第一个愿望，是让小时候的生日会，永远不散场。' } ]
  },
  'l3.dj.check': {
    type: 'check',
    trigger: 'npc:dj',           // 互动街头 DJ，可重复选择路线
    once: false,
    lines: [ { s: 'dj', t: '这条街最酷的人是谁？' } ],
    options: [
      { label: '「Kyujin。」', goto: 'l3.dj.right' },
      { label: '「我自己。」', goto: 'l3.dj.wrong' }
    ]
  }
}
```

## 10. 存档规范（Issue #8，v1：3 存档位 + 手动存档）

- **键**：`mixxtopia.save.v1`（存档位）、`mixxtopia.settings.v1`（声音/触屏按键偏好，独立于存档位）、`mixxtopia.cloud.v1`（逐档同步基线，仅登录后使用）、`mixxtopia.account.v1`（账户会话，仅登录后使用；只存 token 与 user id/email，不含密码/存档内容）；均为 localStorage。
- **发布通道（Issue #17）**：stable 使用上述键；beta/preview 与 stable 在同一个 Pages 域名下运行，localStorage 共享，因此由构建注入的通道名派生独立键：`mixxtopia.save.beta.v1` / `mixxtopia.save.preview.v1`（settings 同理）。stable 保持原键，老玩家存档不受影响；未来 `mixxtopia.cloud.v1` 也应沿用通道后缀，并避免测试环境写入正式 Supabase 项目。测试期只开放 beta 游戏（stable/preview 是占位页，不写存档）；首个稳定版发布后 preview 开放、beta 停用。
- **结构**：

```js
// mixxtopia.save.v1
{
  v: 1,
  slots: [                    // 固定 3 档，空档为 null
    {
      v: 1,
      slot: 1,                // 1–3
      current: 1,             // 继续时载入的关卡 id（通关自动存档后指向下一关）
      unlocked: 1,            // 已解锁到的关卡 id
      cleared: [1],           // 已通关关卡 id
      stars: { '1': ['s1','s2','s3'] },  // 每关已收集星 id
      sheep: 0,               // 黑羊彩蛋计数 0–6
      played: ['l1.intro', 'l1.backstage.arrived'], // once 已播对话节点 id 与非对话到达标记
      updatedAt: 1761260000000 // 最近写盘时间（ms），「继续冒险」取最新档
    },
    null,
    null
  ]
}

// mixxtopia.settings.v1
{ v: 1, sound: true, touch: 'auto' }
// sound：声音开关；touch：触屏虚拟按键显示偏好 'auto'|'on'|'off'（#44）。
// 修改立即生效并写盘，不影响存档位。
```

- **写入时机（手动存档制）**：仅两种操作写盘：
  1. 暂停菜单「保存并退出」：写入当前关、已收集星、cleared/unlocked、黑羊计数、played 进度（once 已播对话节点与后台到达标记），然后回标题；
  2. 通关结算自动存档：在 1 的内容上追加 `cleared`、`unlocked`，并把 `current` 指向下一关（末关停留在末关）。
- **不写盘的操作**：标题「回到标题（不保存）」、直接刷新/关闭页面、新游戏开局（选空档后首次保存或通关才生成存档）、重玩本关。未保存进度丢失，回到上次存档。
- **3 档位交互**：
  - 标题「继续冒险」= `updatedAt` 最新的存档位（有任一存档时显示）；
  - 「选择存档」列出 3 档：显示关卡名、该关星数、已通关数；点击已有档载入，点击空档直接开新游戏；已有档右侧 ✕ 删除（二次点击确认，不可恢复）；
  - 「新游戏」自动占用第一个空档；三档全满时打开选择存档界面，需对目标档二次点击确认覆盖（覆盖只在下一次保存/通关时真正写盘）；
  - **不做选关**：关卡按线性流程推进，`unlocked / cleared` 仅用于存档展示与后续云存档。
- **读档恢复**：`current` 关卡、该关已收集星（实体标记为已收集、传送门点亮）、cleared/unlocked、黑羊计数、played 进度（once 已播对话节点不重播）。第一关的非对话到达标记 `l1.backstage.arrived` 也保存在 played 中；包含此标记且后台入口已解锁时，将玩家恢复到后台入口落点。
- **重玩本关**：本关收集进度重置（星星重新拾取）；上次存档不被改写，只有再次保存才会覆盖。
- **损坏数据**：JSON 非法或结构不符时按空档处理，不抛错；选择存档界面提示「存档数据损坏」，下次保存覆盖。
- **存储不可用**：localStorage 被禁用/写满时「保存并退出」失败，暂停界面提示并停留在暂停态，不丢当前进度；「继续冒险」不显示。
- **无服务器（现状）**：纯本地；清缓存即重置（选择存档界面与帮助界面注明）。
- **游玩统计（#46，本地实现）**：账户设置展示累计时长、成就与逐关收集率；仅 PLAYING 计时，暂停/对话/隐藏页面不计时。时长与成就独立于手动存档，回标题也保留；游客统计仅本机，登录后单独累计。`stats` 经 `merge_stats` RPC 以页面计数的单调毫秒增量合并，断网保留本机 journal，下次同账号登录补传；收集率按三份云存档的星 ID 按关去重后除以地图总星数，各设备一致。上线需应用 `0002_stats.sql`；完整口径与验收见 `ACCOUNT_SYSTEM.md` §12。
- **云存档（Issue #22，#45 已本地实现；2026-10-26）**：后端 **Supabase**（Postgres + Auth），前端**手写 `fetch` 封装**直连 GoTrue / PostgREST，**不引 SDK**，保持零依赖与 Pages 静态部署。正式规格：
  - **保留本地层**：本节 localStorage 存档与云同步互不替代，未登录 / 离线 / 请求失败时一切都按本节本地逻辑跑；
  - **账户（#43）**：`js/auth.js` 手写 GoTrue 封装（注册 / 登录 / 登出 / refresh_token 续期 / 会话恢复），会话存 `mixxtopia.account.v1`（beta/preview 追加通道后缀）；启动时恢复登录态、token 过期自动续期；登出只清该键，不碰存档与设置；未登录零上传；
  - **邮件找回密码（#22，本地实现）**：登录页提供「忘记密码」入口，独立重置页随当前游戏通道发布；通过邮件链接验证身份后设置新密码，不启动游戏或自动合并进度，不改写本机原有账户和游戏数据。恢复令牌不落盘，写入结果不确定时不自动重试。发信服务、回调 allowlist 及真实邮件验收见 `docs/PASSWORD_RECOVERY.md`；本地测试不发送真实邮件。
  - **账户设置（#44）**：登录后从登录面板进入「账户设置」screen（复用 `_show`/`_hide`，不新增游戏状态）；昵称 1–16 字（按 Unicode 码点计，trim 后非空、不含控制字符），头像固定 6 选 1（`muse-1…muse-6`，白名单为 `GAME.avatarPresets`，数据库只校验 id 格式 `^[a-z0-9][a-z0-9-]{0,31}$`，新增头像只需改 data.js、无需数据库迁移；未知 id 渲染回退默认头像），保存走 `PATCH /rest/v1/profiles?id=eq.<uid>` + `Prefer: return=representation`（0 行视为资料缺失），错误统一中文提示；资料加载失败不阻塞本地游玩。
    - **修改密码（#22 扩展，2026-10-28 已实现，尚未发布）**：设置页独立表单要求当前密码、新密码、确认新密码；先重新验证当前账号，再带新会话向 GoTrue `PUT /user` 更新密码。不保存密码，不删除存档；提交 / 离开页面时清空输入，切号时取消旧结果，修改请求不自动重试。当前客户端的真实 REST 改密 / 新旧密码登录 / 数据保留验收已通过，实际部署页面仍待验证，详情见 `ACCOUNT_SYSTEM.md` §12。
    - **防覆盖**：profile 未成功加载前禁用「保存设置」（加载失败显示「重试读取云端资料」），避免表单默认值（NSWER / muse-1）覆盖云端现有昵称/头像；
    - **未知头像保留**：读取时保留云端原始 id（`avatarRaw`），若它不在当前白名单（未来版本 / 旧数据），只改昵称/偏好时 PATCH 省略 `avatar` 字段，不改动云端头像；玩家主动选新头像才回写；
  - **偏好与本地设置（#44）**：`mixxtopia.settings.v1` 是运行时唯一来源（`{ v, sound, touch }`），修改立即生效并写本机；登录后点击「保存设置」才同步到 `profiles.prefs`（标题声音开关、设置页即时切换只写本机；云端只保留 `sound` / `touch`，未知字段丢弃）。采用规则：本机**没有**设置记录（新设备/清缓存）时采用一次云端偏好；本机已有记录则本地优先、不自动覆盖（避免登录后声音突变），设置页提示差异，保存时以本机为准上传云端。**声音/触屏偏好按设备级设置处理**：同设备换账号不自动切换，新设备采用一次后不再跟随云端变化；
  - **删除账户（#44）**：前端只有 publishable key，不能直接删除 `auth.users`；设置页提供「删除账户（提交申请）」链接跳 GitHub issue 模板（URL 预填标题/说明，不要求附个人信息），维护者核实后后台删除，`profiles` / `saves` / `stats` 级联删除、不可恢复（详见 `docs/PRIVACY.md` §5）；
  - **表结构**：`profiles`（昵称、头像 id〔固定集合、前端白名单、不支持上传〕、偏好）、`saves`（`user_id, slot, version, updated_at, data jsonb`，一账号 3 个存档位、一行一个存档位）、`stats`（时长 / 成就）；`data` 与本节存档位结构同构（去掉 `slot` 与 `updatedAt`）。`updatedAt` 由 `saves.updated_at` 列承担：上传时不写入 `data`；下载时必须在调用 `SaveStore.writeSlot()` 前把 `updated_at`（ISO 字符串）转成本地毫秒时间戳写入 `updatedAt`，因为 `normalizeSlot()` 不会从 `updated_at` 补齐该字段（缺失按 `0` 处理）。本地存档位不增加 `version` 字段；逐档同步基线（云端 `version`、本地与云端时间）单独存 `mixxtopia.cloud.v1`（结构见 `ACCOUNT_SYSTEM.md` §9），`normalizeSlot()` 不需要保留额外字段。除时间字段外双向直传、不做字段映射；
  - **安全**：三表全开 RLS，策略只授 `authenticated` 且限本人——`profiles` 用 `auth.uid() = id`，`saves` / `stats` 用 `auth.uid() = user_id`；`anon` 无表权限；anon key 公开，安全边界只在 RLS，必测「A 用户 token 读 B 用户存档 → 失败」；
  - **冲突**：`version` 仅存在于云端（上传乐观锁 + 变更检测），本地不存；登录时用 `mixxtopia.cloud.v1` 的逐档基线判断本机/云端是否改过：只有一边改过则提示对应方向，两边都改过或没有基线则标出本机/云端及各自时间，由玩家逐档手动选择，**默认不自动覆盖、不以时间戳自动判定胜负**；游客登录后提示一次「并入本机进度」，同档冲突同样进入逐档选择；
  - **降级**：云端不可用时显示「未同步」，不阻塞存档与「保存并退出」；同账号未上传进度以持久化 pending 在下次登录/手动重试时补传（版本冲突则停止）；
  - **账号归属 / 操作确认（#45）**：基线额外记录 `userId`、并入选择与 pending，切号不复用旧授权；逐档上传/载入均二次确认，云端或本机在请求期间变化不静默覆盖。本地删除只清本地与基线，保留云端备份；真实通道后端隔离及 RLS 验收见 #17/#47；
  - **不做**：实时多端推送、后台轮询、自动覆盖式合并；
  - 数据模型 SQL、同步时序与隐私要求见 `docs/ACCOUNT_SYSTEM.md`。

## 12. 战斗系统（Issue #18，v1 已实现）

> 2026-10-25 落地。武器：**NMIXX 二代应援棒**。实现位于 `js/engine.js` 的 `Combat` 类与 `COMBAT_TUNING` 常量，`js/main.js` 负责输入、HUD、粒子、音效与绘制；数值唯一真源为 `COMBAT_TUNING`。
>
> 定位不变：剧情/解谜为主，战斗为点缀；敌人以**新增实体**接入，不改动现有地图结构、星数与谜题。HP / 能量是**关卡内临时状态**，不写入存档；换关、重玩、读档均重置。

### 12.1 操作

| 操作 | 键盘 | 触屏 | 说明 |
|---|---|---|---|
| 轻击 | **F** | **B** | 快速、低伤害；射程 24px |
| 重击 | **G** | **C** | 慢、高伤害/高击退；射程与轻击相同 24px |
| 能量炮 | 能量满时按 **F 或 G** | 能量满时按 **B 或 C** | 不区分轻重击，统一释放同一种能量炮 |
| 互动 / 确认 | E / 空格 | A | 原有操作不变 |
| 暂停 | Esc | — | 原有操作不变 |

- **攻击方向自动锁敌**：只锁定**正面 180° 扇形**（以最近一次移动方向为中心线、两侧各 90°）内、攻击范围内、视线未被墙体/关闭门/箱子遮挡的**最近**存活敌人；轻击/重击锁定范围 24px，能量炮锁定范围 52.8px。范围内无可用目标时沿**最近一次移动方向**（八向）出手；无移动时保持上次朝向，初始朝下。
- 轻击/重击共享一个攻击冷却；冷却中按 F/G 无效，但不会吞掉能量炮（能量满且冷却结束时再按即可）。
- 能量满时普通攻击被能量炮替代，必须先把能量炮打出去才能继续普攻。

### 12.2 武器数值（`COMBAT_TUNING`）

| 项 | 轻击 light | 重击 heavy | 能量炮 cannon |
|---|---|---|---|
| 伤害 | 1 | 2 | 6 |
| 射程（玩家中心 → 命中边缘） | **24px** | **24px** | **52.8px = 24 × 2.2** |
| 命中宽度 | 24px | 24px | 32px（穿透光束） |
| 冷却 | 0.26s | 0.55s | 0.8s |
| 演出时长 | 0.14s | 0.22s | 0.32s |
| 命中回能 | +5 | +10 | 0（消耗 100） |
| 击退 | 10px | 18px | 26px |
| 命中数 | 前方旋转矩形内全部敌人 | 同左 | 光束内**全部**敌人 |

- **射程口径**：轻击与重击完全一致（24px，约 1.5 格）；能量炮为 52.8px（2.2 倍），从玩家中心沿锁定方向延伸的光束，命中路径上所有敌人。
- **锁敌规则**：每次出手重新选取正面 180° 内、视线可达的最近敌人（按敌人中心距离）；锁定后方向指向目标中心（可为斜向），攻击判定使用以玩家中心为起点的旋转矩形。无目标时方向 = 移动朝向。
- **视线遮挡**：`findTarget()` 与命中判定都会从玩家中心向敌人中心采样；墙体、关闭的门、箱子会阻断锁定与伤害（水面不挡视线），避免隔墙锁敌/穿墙攻击。
- **被动能量条**：上限 100，游玩中自动 +7/s（约 14.3s 充满）；普攻命中额外回能，普攻击杀 +5；能量炮释放后清空，演出 0.32s 期间暂停回能（HUD 立即归零）。
- 攻击判定为朝向前方的旋转矩形（前向 range + 侧向 width/2，按敌人半身扩展）；敌人被击退时逐轴检查地形/门/箱子，不会被推出地图或穿墙。

### 12.3 HP、受伤与倒下

- 玩家 HP 上限 **10**；敌人接触造成 1 点伤害（可按实体覆盖），随后进入 **0.9s 无敌帧**并沿「敌人 → 玩家」方向击退 14px。
- HP 归零：**无惩罚复位**到本关出生点，满血 + 1.2s 无敌帧，敌人回到出生点；已收集星星、通关用时、能量条数值保留，不进入 Game Over / 结算。
- HUD 显示「♥ 当前/10」与能量条；HP ≤ 3（30%）时红闪。能量满时能量条金色脉冲、标签变为「F/G」，玩家头顶出现闪烁金星。

### 12.4 敌人

| kind | 名称 | HP | 移速 | 仇恨范围 | 接触伤害 | 说明 |
|---|---|---|---|---|---|---|
| `dreamling` | 梦蚀团 | 3 | 36px/s | 96px | 1 | 基础小怪，紫色方块 |
| `wisp` | 梦蚀灵 | 2 | 52px/s | 128px | 1 | 更快、更脆，薄荷绿漂浮方块 |

- 敌人在仇恨范围内朝玩家移动，进入接触距离后停下；移动逐轴检查 `Mechanics.blockedAt`（墙、水、关闭的门、箱子均阻挡）。
- 被击败后消失并保留 `dead` 状态，直到重开关卡/玩家倒下才复位；受击白闪，受伤后头顶显示血条。
- 数据可覆盖 `hp / speed / aggro / damage / size`；缺省值取上表。敌人不写入 `map.rows`，一律作为实体层追加。

### 12.7 接入 API（`js/engine.js`）

- `engine.createCombat(level, opts)` → `Combat`；`opts` 可覆盖 `maxHp / maxEnergy / energy`（测试用）。
- `combat.attack(kind, player, mechanics)`：返回 `{ kind, cannon, damage, range, dir, hits, target, energy, energyFull }` 或 `null`（冷却/倒下）；`dir` 为锁定/移动方向单位向量，`target` 为锁定的敌人 id。
- `combat.findTarget(player, range, mechanics)`：返回正面 180° 内、视线可达的最近存活敌人（`mechanics` 缺省时不做遮挡检测）；`combat.aimDir(player, target)`：返回锁定目标或移动朝向的单位向量。
- `combat.hasLineOfSight(mechanics, x1, y1, x2, y2)`：约 3px 步长采样墙体/关闭门/箱子，返回视线是否通畅。
- `combat.update(dt, player, mechanics)`：推进冷却、能量、敌人 AI、接触伤害；返回事件数组。
- `combat.face(dx, dy)` / `combat.revive()` / `combat.resetEnemies()` / `combat.aliveCount()`。
- 公开字段：`hp / maxHp / energy / maxEnergy / facing / cooldown / swing / invuln / enemies / attackRange / cannonRange`。
