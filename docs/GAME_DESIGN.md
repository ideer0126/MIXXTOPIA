## 1. 设计支柱

1. **梦幻像素** —— 每关独立调色板 + 主题粒子，营造「生日愿望梦境」的整体气质。
2. **剧情驱动** —— 对话推进剧情：打字机效果、角色姓名框、部分节点有选项。
3. **谜题节奏** —— 教学 → 练习 → 综合：关 1 教基础，关 2–5 各练一种机制，关 6 综合收束。
4. **移动优先** —— 触屏虚拟按键单手可玩，键盘/触屏双输入等价。
5. **轻量友好** —— 休闲难度、死亡无惩罚（战斗后置 #18），目标体验是「暖心收星」而非挫败。

## 2. 世界观与剧情线

### 2.1 世界观

- 灵感来源：NMIXX 第六张迷你专辑《Strange Muse》（2026-10-19 发行，主打《긴 소원 (Birthday Wish)》）。
- **官方概念层（据官方专辑概念文与公开报道提炼）**：MIXXTOPIA 是「容纳无数个体的共生世界，更是能让每个人尽情舒展专属自我身份的自由空间」；相聚于此的人各自奔赴向往的生活，又在灵魂深处相连、随时能再度并肩。**「我们互为彼此的专属缪斯」**——NSWER 的存在为缪斯们注入灵感，缪斯们的存在也点亮 NSWER 的日常。这里每天都在上演为全新缪斯准备的生日派对：吹熄蜡烛、许下心愿，永远在为彼此许下「Birthday Wish」。
- **神话倒影层（同人二创）**：希腊神话中，缪斯（Muses）是宙斯与记忆女神谟涅摩叙涅的女儿、司掌音乐与灵感的女神；九位缪斯的「九」暗合月相周期。本作中，六位成员即六位缪斯的化身；**MIXXTOPIA** 是灵感之泉（赫利孔山的灵感泉 Hippocrene）在梦境中的倒影。梦境里每一位缪斯都有一重「神话倒影」：Lily 倒映珀耳塞福涅（春之少女/冥后）、Haewon 倒映哈迪斯（冥王）、Sullyoon 倒映阿芙洛狄忒（爱与美，执丘比特之箭）、Bae 倒映德墨忒尔（丰收与大地）、Kyujin 倒映宙斯（天空与王座）、Jiwoo 倒映赫尔墨斯（信使与里拉琴）。完整对照与故事梗概见 §2.4。
- 参考《Strange Muse》概念预告与 MV 的公开解析（六人化身缪斯、紫罗兰天空下的马群/飞马意象、黑羊概念），本作加入：紫罗兰色天空与飞马（Pegasus）、黑羊彩蛋 NPC。

> 备注：用户提供的抖音图文解析（https://v.douyin.com/oq8yY83bGyA/ ）此前在本环境无法直接访问；2026-10-23 用户将 12 张截图直接提供，经本地 OCR 识别出完整内容（神话对应、四季循环故事），本节与 §2.4、§8 台词已按该解析落笔。OCR 原文存档于会话工作区 `.ds/ocr/`（不入库）。

### 2.2 剧情线

NSWER 在生日夜对流星许下长愿，被星光引入梦境世界 MIXXTOPIA——一个每天都在举办生日派对的共生世界，NSWER 与缪斯们「互为彼此的专属缪斯」。六位缪斯许下的六个愿望化作 **25 颗愿望之星**，散落在六个梦幻区域；每散落一颗星，梦境的光就暗一分，灵感之泉随之干涸。玩家走遍六个区域、与缪斯对话、解开谜题、集齐全部星星，点亮许愿蛋糕——灵感之泉重新涌流，飞马掠过紫罗兰天空，生日愿望得以实现。六位缪斯各自的神话倒影（§2.4）随旅程逐关揭开：珀耳塞福涅的四季、赫尔墨斯的信使之路、宙斯的默许、月夜的重逢、大地的荒芜与复苏、疾风中的团聚。

### 2.3 结局

1. 25 星全部归位 → 许愿蛋糕逐层点亮 → 灵感之泉复涌，化作星光河。
2. 飞马掠过紫罗兰天空，载 NSWER 飞向黎明；耳边响起「긴 소원을 부릅니다, 응답하라 NSWER」。
3. **黑羊彩蛋**：6 关各藏一只黑羊 NPC，各说一句神话谜语；集齐 6 句，结局追加一段隐藏画面（M3 可选内容，不阻塞主线）。

**概念预告故事梗概**（供 §8 台词引用，不作独立剧情节点）：

1. 爱与美之神阿芙洛狄忒（Sullyoon）看不惯冥王哈迪斯（Haewon）对爱情无动于衷，让丘比特向哈迪斯射出金箭；哈迪斯不可救药地爱上珀耳塞福涅（Lily）。
2. 明知德墨忒尔（Bae）不会同意，哈迪斯求得宙斯（Kyujin）默许，在山谷掳走了采花的珀耳塞福涅，带回冥界结合；只有太阳神与月亮女神目睹了一切。
3. 德墨忒尔悲伤欲绝，大地荒芜、颗粒无收；宙斯派信使赫尔墨斯（Jiwoo）下冥界调停，珀耳塞福涅回到人间，世间恢复生机——这一组构图参考名画《创造亚当》，赫尔墨斯出现时伴随里拉琴的乐声（里拉琴：赫尔墨斯发明 → 转交阿波罗 → 再传缪斯九女神，呼应专辑名 Strange Muse）。
4. 但珀耳塞福涅吃下了冥界的石榴籽，注定每年一半时间返回冥界：归来则大地复苏，离去则万物萧瑟——四季由此形成。
5. 阿芙洛狄忒爱上凡人美少年阿多尼斯，阿多尼斯意外重伤而死，血中开出红玫瑰；阿芙洛狄忒的哀悼使他年年复生——一半时间与她相聚，一半在冥界陪伴冥后（Lily）。镜子中无限的镜像 = 循环往复；德墨忒尔与阿芙洛狄忒都活在「与所爱之人团聚又分离」的循环里，也都造就了四季。
6. 彩蛋钩子：丘比特（Sullyoon）向哈迪斯射箭的画面，早在 2025 年 10 月的 Game Face 相关物料中就有伏笔；小夜曲（Heavy Serenade）副歌开头的 Sullyoon 射箭动作亦与此呼应。

**可引用的官方词句**（歌词/概念文意译，仅作台词氛围参考，不照搬歌词）：「吹熄蜡烛、许下心愿，我们永远在为彼此许下 Birthday Wish」；「你于次元缝隙间与我相见，初见，即是我们的生日」；「我会守护你的梦到天亮，直到宇宙的星星全部熄灭，明天见」；「不为周遭喧闹所动」（Hot 'n Unbothered）。

## 5. 关卡详细设计

### 5.1 关 1 · Birthday Wish（生日烛光梦境）

- **氛围**：巨大的许愿蛋糕、礼物盒、熄灭的蜡烛、飘落的星尘。全员登场。
- **教学点**（按序）：① 移动 ② 收集星星 ③ 推礼物盒 ④ 压力开关开门 ⑤ 与 NPC 对话 ⑥ 传送门过关。

| # | 星星 | 位置 | 获取方式 | 教学点 |
|---|---|---|---|---|
| ★1 | 入门星 | 主路中央（可见） | 直接走过去收集 | 移动 + 收集 |
| ★2 | 礼物星 | 礼物盒后方 | 互动推动礼物盒后收集 | 推箱 |
| ★3 | 全员星 | 与 6 位缪斯全部对话后，在蛋糕旁生成 | 对话计数 6/6 触发 | 对话推进 |

**谜题表**

| 元素 | 数量 | 行为 |
|---|---|---|
| 压力开关 SWITCH | 1 | 踩上（或推箱压上）→ 开启对应门 |
| 门 GATE | 1 | 挡在主路出口，由开关控制 |
| 礼物盒 BOX | 2 | 可沿推的方向滑动一格，可压开关 |
| 缪斯 NPC | 6 | 各有一段自我介绍台词，全部对话后生成 ★3 |
| 引导精灵 Byeori | 1 | 传送门旁待机，结算台词 |
| 黑羊 SHEEP | 1 | 彩蛋谜语（§8.7） |

### 5.2 关 2 · Kerosene（灯油与火焰）

- **氛围**：昏暗的灯柱长廊，火焰点亮黑暗；Jiwoo 在入口迎接。
- **机制**：灯油罐（OIL）可拾取携带（一次一罐）；走到灯柱（LAMP）旁互动即点燃灯柱并消耗灯油；每点燃一根灯柱，其 `target` 字段绑定的门（GATE）打开（L1→G1、L2→G2、L3→G3）。

| # | 星星 | 位置 | 获取方式 |

## 7. 对话系统规范

- **样式**：底部对话框 + 姓名标签（§3 角色色；`nar` 使用 §3 旁白样式）；打字机 25ms/字；E/空格/点击翻页；选项用 ↑↓ 移动 + 确认键。
- **触发**：靠近 NPC 按互动；TRIGGER 区域自动触发；`once` 节点只播一次，`repeat` 节点可反复（提示类）。
- **节点类型 × 触发来源**（#12 转录时每个节点必须挂一种类型）：

| 节点类型 | 触发来源 | once | 说明 / 示例 |
|---|---|---|---|
| intro | NPC 互动（首次） | true | 开场剧情；结束后该 NPC 互动经 `next` 指向 hint |
| hint | NPC 互动（此后） | repeat | 提示类，如 `l1.lily.hint`、`l2.jiwoo.hint`、`l3.hint`、`l4.lily.hint`、`l4.haewon.hint`、`l5.sullyoon.hint`、`l5.bae.hint`、`l6.hint` |
| npc | NPC 互动 | true | 一次性自我介绍 / 氛围台词，如 `l1.npc.lily`、`l4.npc.sullyoon`、`l5.npc.lily` |
| check | NPC 互动 | false | 可重复的选项检查，如 `l3.dj.check` |
| star | 收集星星事件（自动） | true | 收集反馈台词，如 `l1.star1` |
| clear | 过关事件（自动） | true | 结算台词，如 `l1.clear.1` |
| sheep | 黑羊互动 | true | 计数 sheep +1，如 `l1.sheep` |
| cutscene | 关卡加载 / TRIGGER / CAKE 自动 | true | 序章 `p0.*`、结局 `l6.end.*` |

- **`trigger` 取值约定**（与上表触发来源一一对应，规则 7 校验）：NPC 互动 → `npc:<speaker>`（首次/此后由节点类型决定）；收集星星 → `star:<星id>`；过关 → `clear:<scopeId>`；黑羊 → `sheep:<黑羊实体id>`；关卡 / 场景加载 → `load:<scopeId>`；TRIGGER 区域 → `trigger:<trigger实体id>`；蛋糕 → `cake`。
- **字段约束**：每个节点必填 `type`（上表 8 种之一）与 `trigger`（按取值约定），二者冗余声明、不可矛盾（如 `type:'check'` 配 `trigger:'npc:dj'`）。
- **自动对话作用域**：trigger 为 `clear:<scopeId>` / `load:<scopeId>` 的节点另须填写所属关卡或场景的 `scopeId`，其字符串形式必须等于 trigger 的后缀：关卡节点 `lN.*` 的 `scopeId` 必须为 N（如 `scopeId:1` 对应 `clear:1`），序章节点 `p0` 的 `scopeId` 必须为 `'p0'`（对应 `load:p0`）。关卡 ID 来自 `GAME.levels[].id`，独立场景 ID 来自 `GAME.scenes` 的键（见 §11），二者字符串形式不得重名；`clear` 仅用于关卡。每个已配置的「作用域 + 事件类型」恰有一个 `entry:true` 入口，事件仅调度该入口；同一演出的后续节点保留相同 `scopeId` 与 `trigger`、设 `entry:false`（缺省 false），由 `next` 串联且均须从入口可达，不能再次注册为自动入口。**`entry` 机制仅适用于 `clear:` / `load:` 自动作用域；`star:<星id>` / `sheep:<id>` / `cake` 的自动节点按 trigger 直接调度，不设 `entry`**（与 tools/validate.js #30 校验约定一致）。
- **黑羊绑定**：关 N 的黑羊实体使用全局唯一 `id:'sheepN'`、`dialogue:'lN.sheep'`（N = 1–6），对应节点为 `type:'sheep'`、`trigger:'sheep:sheepN'`、`once:true`。互动只播放该实体绑定的节点，首次播放计数 +1；保留每关一句、集齐 6 句追加结局画面的行为。

- `next` 指向的节点必须存在（§11 规则 7 校验）。
- **对话期间**：玩家定身；关 5 清凉条计时暂停；战斗接入后敌人生成暂停（#18）。
- **快进**：按住互动键加速打字；整段跳过 = 双击翻页键（预留）。
- **数据格式**（#12 直接照此接入 data.js）：

```js
dialogue: {
  'l1.intro': {
    type: 'intro',               // 节点类型（§7 上表 8 种之一，必填）
    trigger: 'npc:lily',         // 触发来源：与 Lily 首次互动（§7 取值约定，必填）
    once: true,
    lines: [ { s: 'lily', t: 'NSWER！生日夜能在这里见到你……' }, ... ],  // 即 §8.2 的 l1.intro.1–5
    next: 'l1.lily.hint'          // 结束后将 NPC 互动指向 hint 节点
  },
  'l1.clear': {
    type: 'clear', scopeId: 1, trigger: 'clear:1', entry: true,
    once: true,
    lines: [ { s: 'lily', t: '三颗愿望之星全部归位。传送门，开门！' }, ... ]
  },
  'p0': {
    type: 'cutscene', scopeId: 'p0', trigger: 'load:p0', entry: true,
    once: true,
    lines: [ { s: 'nar', t: '生日夜的钟声，敲过第十二下。' }, ... ]
  },
  'l1.sheep': {
    type: 'sheep', trigger: 'sheep:sheep1', once: true,
    lines: [ { s: 'sheep', t: '第一个愿望，是让蜡烛永远为过生日的人点亮。' } ]
  },
  'l3.dj.check': {
    type: 'check',
    trigger: 'npc:dj',           // 互动街头 DJ，可重复挑战
    once: false,
    lines: [ { s: 'dj', t: '这条街最酷的人是谁？' } ],
```

## 10. 存档规范

- **键**：`mixxtopia.save.v1`（localStorage）。
- **结构**：

```js
{
  v: 1,
  unlocked: 1,            // 已解锁到的关卡号
  current: 1,             // 当前关
  stars: { 1: ['s1','s2','s3'], ... },  // 每关已收集星 id
  cleared: [],            // 已通关关卡
  sheep: 0,               // 黑羊彩蛋计数 0–6
  settings: { sfx: true, bgm: true }
}
```

- **写盘时机**：收集星星、通关、切换关卡、返回标题；不改写历史最高进度。
- **重玩/重试**：重玩本关或清凉条见底回起点时，本关内已收集星星保留（不重复计数）。
- **无服务器（现状）**：纯本地；清缓存即重置（帮助界面注明）。
- **云存档（预留，#19 立项）**：账户系统（注册/登录、账户设置、云同步、统计）已立项，技术路线 Supabase / Firebase 二选一、**待评审**（立项稿见仓库 `docs/ACCOUNT_SYSTEM.md`）。落地原则：保留本节本地层，新增云端同步层；云端文档沿用本结构并增加 `version` / `updatedAt` 字段做冲突检测（以新覆盖或手动选择）；RLS 仅本人可读写，游客数据仍仅存本地。评审通过后再并入本节正式规格。

```js
  dialogue: { /* §8 全部台词，格式见 §7 */ },
  saveKey: 'mixxtopia.save.v1'
};
```

**校验规则（tools/validate.js 必须覆盖）**：
1. 地图尺寸 ≥ 40×28，行数 = h、每行长度 = w；
2. tile 字符全部存在于该关 legend；实体（星星/机关/NPC）不得落在墙等永久不可通行瓦片上；WATER、STEPSTONE 及浅滩星允许按 §6 叠放在水域，动态通行性由规则 9 校验；
3. 每关 starCount 与 entities 中 star 数量一致，且在 3–5 之间；总星数 = 25；star id 全局唯一；
4. spawn 恰好 1 个；关 1–5 portal 恰好 1 个；关 6 cake 恰好 1 个；每个 portal.to 必须引用已存在的关卡 ID，且按线性流程等于当前关卡 `id + 1`；
5. switch.target 与 lamp.target 引用的 gate 存在；trigger.rect 完整落在地图范围内（0 ≤ x 且 x+w ≤ 地图宽，0 ≤ y 且 y+h ≤ 地图高）；关 2 灯柱数 = 灯油数 = 门数 = 3；
6. oneway.dir ∈ {N,E,S,W}；wind.dir 同理；关 4 每个 `~` 格恰有一个同坐标 WATER，每个 WATER 必在 `~` 上，`shallow` 为布尔值，初始 `waterLevel` 均为 `high`（运行时仅允许 `high` / `low`）；每个 STEPSTONE 必须与 WATER 同格；
7. 对话引用、触发来源与作用域：
   - npc.dialogue、sheep.dialogue 与 trigger.dialogue 引用的对话节点存在；dialogue.next、option.goto 指向的节点存在；每个对话节点必有 `type` ∈ {intro,hint,npc,check,star,clear,sheep,cutscene} 与 `trigger`，且符合 §7 的类型与触发来源约定；trigger 引用的实体存在（`npc:<speaker>` 的 NPC、`star:<星id>` 的星、`trigger:<id>` 的 trigger 实体）；
   - 每个黑羊实体必有全局唯一 ID，`sheep.dialogue` 指向的节点必须为 `type:'sheep'`、`once:true`，trigger 必为 `sheep:<该实体id>`；反向检查每个 `sheep:<id>` 引用的黑羊实体存在且其 `dialogue` 指回此节点，实体所属关卡与节点 `lN.sheep` 的关卡一致；
   - `clear:<scopeId>` / `load:<scopeId>` 的后缀必须与节点 `scopeId` 的字符串形式一致，并引用已存在且无歧义的所属关卡 / 场景 ID（`clear` 仅限关卡）；按 §7 校验节点 ID 所属关卡 / 场景与 scopeId 一致；同一作用域与事件类型恰有一个 `entry:true` 入口，其余节点非入口且由该入口通过 `next` 可达，链内 `scopeId` 与 trigger 相同（`entry` 仅对 `clear:` / `load:` 生效；`star:` / `sheep:` / `cake` 节点按 trigger 直接调度，不设 entry）；
   - 每条对话行的 speaker（`lines[].s`）在 characters 字典（id 全集见 §3 对照注，含 `dj`/`sheep`/`nar`/`all`；伪说话人 `nar`/`all` 同样校验，不要求有对应 NPC 实体）；
8. 每关 NPC 出场与 §5 出场表一致；黑羊每关 1 只；
9. 可达性按合法机制状态与状态转换校验（预留自动校验）：
   - `GATE.open:false` 阻挡、`true` 可通行；ONEWAY 的进入与离开移动方向均须等于其 `dir`，反向与侧向均不可穿过；WATER 高水位仅同格有 STEPSTONE 时可站立，低水位 STEPSTONE 隐没且仅 `shallow:true` 可站立，其余水面落水回本岸（保留已收集星星），不可当作跨湖路径；
   - 从 spawn 与初始状态（门关闭、灯柱未燃、水位 high）出发搜索有向状态图；状态至少包含玩家 / 箱子位置、门 / 灯柱 / 灯油状态、水位、风向、剧情解锁条件与已收集星集合，以及落水复位所需的本岸位置。边仅允许 §5 / §6 定义的合法移动、推箱、踩开关、携油点灯、可互动位置的水位 / 风向切换、对话选项等操作；不得直接假设门已开或远处开关已按下。必须存在同一次游玩中集齐本关所有星星并到达已激活传送门的路径（关 6 为集齐总计 25 星后到达蛋糕），不能仅合并互不兼容状态下的可达区域；
   - 普通 flood fill 仅作固定机制状态下的地形连通辅助，不能代替上述校验。场景须覆盖：关 1 / 2 的合法开门前后路径；关 3 的单向门禁止逆行及 DJ 两条分支同关内收齐星；关 4 从初始高水位经可达开关切至低水位走浅滩、再切回高水位走两组浮桥并到达传送门，以及桥消失后的落水复位；关 6 的开门 / 单向门与风向切换组合；
10. UI/存档文案无「玻璃碎片」等遗留占位。
