# 按场景加载与运行图片（Issue #95）

[Issue #95](https://github.com/ideer0126/MIXXTOPIA/issues/95) 承接 #93 / #94。

## 行为

标题页不再创建场景图片请求。新游戏进入序章时只请求卧室背景；进入第一关时请求礼堂组，开始套圈才请求小游戏组，进入后台才请求后台组。图片按原始素材路径缓存，跨场景共享人物图集只请求一次。后台存档恢复先确定房间，再加载后台组；重玩返回礼堂并复用已有图片。

加载不参与剧情、碰撞或存档状态变更。图片未到达或损坏时继续使用已有的背景/人物降级绘制，套圈保留可见的绘制泳圈；失败图片可以在再次进入场景时重试，序章背景在重新开局时重试。浏览器额外验证了所有 WebP 解码失败时仍可进入小游戏并暂停/恢复；恢复有效图片响应后，重新进入套圈会仅重试三张小游戏贴图，无需刷新页面。

参考 [Phaser 按场景加载与共享纹理缓存](https://docs.phaser.io/phaser/concepts/loader)，沿用本项目原生 Image + Map，不引入运行时加载库。

## 美术与运行文件

- `assets/` 下原始 WebP 保留，用于美术编辑和现有图集坐标定义。
- `assets/runtime/` 是通过 Pillow 生成、纳入版本控制的运行用 WebP。
- `assets/runtime/manifest.json` 及 `js/runtime-images.js` 记录源尺寸、运行尺寸和运行路径；浏览器不另外请求 JSON。
- 发布构建删除原尺寸图片，只携带运行图；仍适用于静态服务器、Pages 子目录和本地 HTML。
- 绘制时将原图取样坐标按宽高比例映射到运行图，目标坐标、人物脚底、动作速度、地图和碰撞不变。

尺寸策略：封面 128×128；头像图集最长边 384；序章与套圈背景最长边 960；其他图集和立绘最长边 768。礼堂整图需要整房间的细节，最长边上限 1920，现有 1500×1049 原尺寸保持。像素图采用最近邻缩小，封面采用 Lanczos；输出均为无损 WebP。缩图会减少原始细节，不能宣称与原尺寸解码像素一致。

重新生成（本次使用 Pillow 12.3.0 / libwebp）：

```bash
python3 -m pip install Pillow==12.3.0
npm run images:build
npm run test:build
python3 tools/test-runtime-images.py
```

导出完成后会清理 `assets/runtime/` 中不再对应源图的旧 WebP，保留本次输出及非图片文件，避免删图或改名后仍发布旧图。定向检查使用临时目录覆盖源图删除 / 改名、清单及透明像素。

现有构建使用已生成并入库的图片，不要求 CI 安装 Pillow。

## 验收

- 第一关校验、JS 语法、引擎/主逻辑/账户/存档/统计/套圈/碰撞/找回密码及构建测试通过；默认全量地图仍为既有 48 项错误。
- 桌面、触屏竖屏和横屏验证标题零图片、序章独立加载、第一关完整通关、后台存档直接继续、重玩缓存复用及独立找回页。
- 实际 file:// 页面验证人物缓存、对话后移动及暂停/恢复；HTTP 页面验证演奏局部帧固定与前景轮廓遮挡。
- 找回密码 12 组浏览器桩检查，无真实邮件或后端写入。
- 画面对比关注人物比例、透明边缘、背景、家具和遮挡；原图与运行图有缩放取样差异。
